1. Idempotency and safe methods

B Correct. Idempotent means calling the operation multiple times has the same effect as calling it once. GET (and HEAD) are “safe”: they should not change server state. POST often creates new resources each time, so repeating it may not be idempotent unless the API is designed that way.

2. 401 vs 403

B Correct. 401 says “who are you?” — missing or invalid credentials. 403 says “I know who you are, but you may not do this” — authorization failed. Interviews love this distinction.

3. 502 Bad Gateway

B Correct. Your server is the gateway: it called another service (Open-Meteo) and could not get a good response. That is different from 500 (your own code broke) and 400 (the client sent bad input).

4. OPTIONS and CORS preflight

B Correct. Cross-origin requests with certain methods or headers trigger a preflight OPTIONS request. The server answers with allowed origins and methods; the browser then sends the real POST if allowed.

5. Origin

B Correct. Same host but different port = different origin. That is why your frontend on 8000 calling the backend on 8001 needs CORS headers on the backend.

6. GET and request bodies

B Correct. REST convention puts read parameters in the query string. Caches and tools assume GET is safe and repeatable; bodies on GET are undefined in practice and break expectations.

7. Content-Type

B Correct. Headers describe the message. Content-Type on the request tells the server how to interpret the body. On the response, it tells the client what the body is (often application/json).

8. DNS

B Correct. TCP needs an IP address. DNS maps names to IPs. HTTP and JSON sit above TCP; they do not replace DNS.

9. Port number

B Correct. A host can run many services; the port selects which process accepts the connection. Default HTTPS is 443; your local backend might use 8001.

10. DELETE in REST

A Correct. HTTP verbs suggest intent: GET read, POST create/submit, PUT/PATCH update, DELETE remove. The path identifies which resource.

11. fetch and json()

B Correct. fetch gives you headers and status immediately; the body is a stream you read once. json() parses UTF-8 text into objects. Check response.ok or status before assuming success.

12. API keys in URLs

B Correct. Secrets in URLs leak via server logs, proxies, and browser history. Headers like Authorization or a custom API-key header are common alternatives.

13. 500 Internal Server Error

B Correct. The request reached the server and looked valid enough to process, but the server failed internally. Fix the server code or dependencies; do not blame the client format unless you also return 400.

14. Latency

B Correct. Each hop (browser → backend → Open-Meteo) adds round-trip time and processing. Calling Open-Meteo once per city multiplies that work — a common design tradeoff.

15. Backend as BFF / gateway

B Correct. The backend is a boundary: it enforces rules, hides upstream details, and keeps the frontend simple. This matches your weather app architecture.
